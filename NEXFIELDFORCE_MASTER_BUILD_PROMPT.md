# NexFieldForce — Reusable Master Build Prompt

Copy everything below into a coding agent that has access to an existing React/Node repository. Replace the bracketed brand and colour tokens before starting. Do **not** include passwords, API keys, production exports, customer records, staff records, database dumps, or uploaded files in the prompt.

---

## Prompt starts here

You are a principal product engineer, enterprise HR systems architect, security engineer, backend engineer, database designer, QA lead, and product designer. Build a production-ready, mobile-first workforce operating system called **[BRAND_NAME]**. It is a web application for workforce management, HR, attendance, field operations, commercial sales, inventory, delivery, task collaboration, reporting, and management intelligence.

Work in the existing repository. Preserve working features. Make additive, backwards-compatible changes. Do not use BigInt, BigSerial, UUID-as-primary-key, fake data, sample employees, sample customers, seeded passwords, hard-coded administrator emails, hard-coded organization addresses, or hard-coded company phone numbers. Use `INTEGER GENERATED BY DEFAULT AS IDENTITY` primary keys for application database tables and retain external authentication UUIDs only as optional `auth_user_id` links.

The finished app must run as a public web app on Vercel with Supabase PostgreSQL and Supabase Storage. It must also retain a documented standalone Node.js + MySQL deployment path for cPanel/Hostinger. Do not put secrets in Git. Use environment variables and provide example files containing only variable names and safe example values.

### 1. Product and brand

Use this product identity:

- Product: **[BRAND_NAME]**
- One-line description: Workforce, field operations, commercial sales, and project collaboration.
- Geographic defaults: Nigeria, `Africa/Lagos`, NGN, Nigerian phone normalization.
- Visual direction: change all colours from the existing product to **[PRIMARY_COLOR]**, **[ACCENT_COLOR]**, and **[NEUTRAL_PALETTE]**. Create a distinctive polished visual system; do not copy an existing brand’s colours or logo.
- Include dark and light modes, accessible contrast, reduced motion support, keyboard navigation, responsive layouts, loading states, empty states, retry states, and useful inline error messages.
- The login page should feel premium and calm: value proposition, clear sign-in form, password recovery, an accessible show-password button, responsive two-column desktop layout and single-column mobile layout. It must never contain previous product names or company data.
- Build a small original SVG logo mark and update favicon, PWA manifest, service-worker cache key, title, social metadata, receipt branding, email branding, and all user-visible labels.

### 2. Required stack

Use this architecture unless the existing repository requires an equivalent:

- Frontend: React, Vite, Tailwind CSS, Lucide icons, React hooks, responsive component architecture.
- Backend: Node.js 20+, Express, ESM modules, REST API under `/api`.
- Hosting: Vercel serverless API and Vite static client. Include `vercel.json` with build command, API rewrite, static rewrite, security headers, and a scheduled daily report endpoint.
- Production cloud database: Supabase PostgreSQL through `@supabase/supabase-js`. Use a server-only service-role client for trusted backend access. Use the publishable/anon key only in the browser.
- Standalone alternative: MySQL adapter for Hostinger/cPanel, including schema and deployment instructions. Vercel must use Supabase; do not attempt to run MySQL from Vercel.
- Authentication: Supabase Auth for production identity plus application profiles in `public.users` and `public.employees`. Authenticate with email, phone, or staff ID. Passwords in the app profile use bcrypt only as a compatibility/fallback verifier; Supabase Auth is authoritative in cloud production.
- Tests: Node test suite for business logic and route contracts, plus production build check. Test meaningful paths rather than merely testing implementation details.

### 3. Security and production rules

Implement these as requirements, not suggestions:

1. Server-side authorization controls every protected endpoint. Never rely only on hidden UI controls.
2. All records are scoped by `company_id` and checked against the authenticated user’s company.
3. Validate every request: types, ranges, pagination, date formats, file type, file size, ownership, and role.
4. Rate-limit sign-in, password recovery, task collaboration messages, and other abuse-prone endpoints.
5. Use HTTP security headers, CORS allow-list from `CLIENT_URL`, input validation, structured errors, safe server logs, and audit records for sensitive actions.
6. Never expose service-role keys, SMTP credentials, AI keys, or passwords to the browser or repository.
7. Supabase RLS must be enabled for private application tables. Browser access is minimal. Trusted backend access uses `service_role`.
8. Use public storage only for approved non-sensitive field/sales images. Use a private storage bucket for payslips, signatures, settlement proof, and staff documents. Generate signed URLs for private files and delete files safely by verified bucket/path.
9. Password creation and reset require at least 12 characters. Mark newly provisioned staff as requiring a password change.
10. Support soft deletion for staff: do not destroy employment history. A recoverable archive state must prevent sign-in, attendance, and normal listing; HR can restore it. The UI button should say **Archive staff** unless an explicit permanent purge workflow exists.
11. Do not track keystrokes, typed content, screenshots, audio, or video as productivity monitoring. Inactivity reporting only records coarse app interaction/presence timestamps and clearly explains this to staff.

### 4. Roles and permissions

Create a role system where permissions are assigned by role rather than by special emails. Include:

- `SUPER_ADMIN`: full tenant administration, edit employee IDs, archive/restore staff, password resets, company settings, roles, work locations, audits, reports, integrations.
- `ADMIN`: operational administration, staff management, locations, reporting, commercial oversight.
- `CEO`, `CTO`, `IT_ADMIN`: executive and technology management views according to role.
- `HR_MANAGER`, `HR`: employee directory, recruitment, onboarding, leave, attendance review, work-location assignment, reports.
- `MANAGER`, `SUPERVISOR`: team schedules, task oversight, assigned team attendance and location visibility.
- `ACCOUNTANT`, `SENIOR_ACCOUNTANT`: finance, settlement, payroll/payslip access only within authorised scope.
- `SALES_MANAGER`, `SALES_AGENT`, `FIELD_AGENT`, `BRAND_AMBASSADOR`, `PROMOTER`: commercial/field workspaces with least privilege.
- `STAFF_MEMBER`: own profile, own attendance, own tasks, own leave, notices, collaboration where they are a member.

Colleagues must be able to assign tasks to one another within a shared project when they are project members. Managers may create projects and assign broader team work, but the collaboration module must not artificially limit peer-to-peer task assignment.

### 5. HR, employee identity, and employee numbering

Build these HR features:

- Staff directory with search, filters, profile drawer, role/rank/department, status, supervisor, work location, documents, leave, attendance, tasks, and audit history.
- Staff creation by authorised HR/admin only. Require first name, last name, a valid email or Nigerian phone, department, role/rank, and initial password or generated temporary password. Allow staff to be created without an assigned location, but require a location assignment before they can use location-restricted sign-in or attendance.
- Spreadsheet import: upload XLSX/CSV, preview mapping and validation errors, avoid duplicate email/phone/staff IDs, choose update vs create, and commit only after review. Provide an empty import template. Never store the uploaded spreadsheet in Git.
- Editable staff details, with super admin ability to correct employee number/ID after a deliberately validated workflow. Record the reason and retain a correction audit trail.
- Staff archive/restore with a visible confirmation and audit record. Archived staff cannot authenticate, create attendance, or appear as active.
- Department codes and permanent employee ID rules:
  - Finance `FIN`; Human Resources `HR`; Information Technology `IT`; Sales & Marketing `SM`; Operations `OPS`; Strategy `STG`; Creative `CRE`; Compliance `CMP`; Procurement `PUR`; Executive `EXE`.
  - Format exactly `[DEPT-CODE][YYYY][SEQUENCE]`, e.g. `IT20260001` and `FIN20260001`.
  - Year is hiring year, sequence is four zero-padded digits, unique per department/year, generated atomically on the server/database.
  - Sequence is “dumb” after its prefix: it has no personal information.
  - IDs are never recycled after a staff member leaves. Corrections must not accidentally reuse a previously issued ID.
  - Do not produce timestamp-like IDs, phone numbers, `VERIFY-*`, `EMP-XLSX-*`, or BigInt-like IDs.
- Leave management: leave types, configurable annual balances, leave requests, approvals/rejections, leave history, balances per staff/year/type, and a normalized schema with all expected columns, including annual leave where the interface requires it.
- Recruitment/onboarding pipeline, birthday/anniversary notices, announcements, policy/document compliance, and org chart.
- Payroll/compensation: salary/allowance fields protected from ordinary staff, payslip generation and private storage of payroll documents.

### 6. Workplace, attendance, clock-in, and geofencing

Implement robust location-aware workforce attendance:

- Work locations contain name, type, address, latitude, longitude, status, and geofence radius. Validate coordinates server-side.
- HR/admin can create, edit, deactivate, and assign locations to staff. Assignment history records prior location, new location, reason, actor, start/end date, and whether it is primary/active.
- Market locations use a fixed **300 metre** radius. Other locations may use a configurable radius with sensible limits.
- Staff sign in normally, then must complete a workplace location challenge if the account has an active assigned work location. Require browser GPS only at this point and explain why. Do not request background location permission.
- On leaving the assigned geofence during a location-restricted active session, record a movement event, notify HR/admin, revoke the workplace session, and require return to an assigned work location for the next location-restricted sign-in. Keep clear staff-facing reasons and an audited override route for authorised HR.
- Attendance windows in Africa/Lagos time:
  - Morning clock-in: 08:00–09:00.
  - Late clock-in: 09:00–10:00, marked late.
  - Midday clock-in: 12:00–13:00.
  - Evening clock-out: 17:00–18:00.
  - After a window closes, show a clear explanation and send an authorised exception/override request rather than silently accepting invalid attendance.
- Attendance data includes clock-in/out timestamps, coordinates, accuracy, addresses if available, verified location, radius, status, late/exception state, and approved override details.
- Include timesheets, roster/schedules, attendance exports, HR review and employee self-service views.
- SOS/panic beacon: staff can submit emergency coordinates, accuracy, message, time, and status. HR, supervisors, and administrators can see, acknowledge, resolve, and audit it. The database schema must include all fields used by this feature, including `accuracy`.

### 7. Workforce activity and movement monitoring

Implement ethical monitoring with clear visibility:

- Browser presence heartbeat and user interaction timestamp; do not collect content or screenshots.
- Inactivity threshold is **60 minutes** (not 10 minutes). The server decides whether a flag is created. Multiple tabs/retries must not generate duplicates.
- Record unconfirmed connectivity loss separately from verified inactivity.
- Send HR/admin a notification that an activity gap was detected; present the staff member with a way to explain it. The notice must state that it does not prove they stopped working.
- Track field/assigned-workplace movements at a high level: location login, workplace departure, geofence return, session revoked. Notify HR/admin through the existing notification centre.
- Provide HR dashboards and an executive activity brief with factual counts, time ranges, evidence links, and uncertainty labels.

### 8. Collaboration, task scheduler, and project workspaces

Create a Slack-like internal project collaboration module:

- Projects with owner, members, roles, status, colour, description, and company scope.
- General channel created with every project, additional channels, direct project messages, threaded replies, mentions, notices, and project activity events.
- Tasks have title, description, project, creator, one or more assignees, priority, status, scheduled time, due date, reminders, recurrence, origin task, comments/events, and safe idempotency keys.
- Project members can create and assign tasks to fellow members. Task assignment creates a notice for each assignee.
- Personal “Today” centre and team/project views: overdue, due today, upcoming, completed, incomplete tasks by employee and project.
- Daily schedules/rosters and reminders for HR/supervisors.
- Do not seed fake projects, tasks, messages, or employee collaboration data.

### 9. Commercial sales, field work, inventory, warehouse, and delivery

Preserve/build the following modules with RBAC and company scoping:

- Customer/outlet directory, customer geolocation map, territory assignment, store registration, visits, field audit, proof-of-visit, photos, signatures, competitor intelligence, route/waypoint work.
- Sales orders with calculations, products/catalogue, discounts, targets, commissions, settlements, collections, receipts, and exports.
- Receipt design must be print-friendly and professional: company logo/mark, configurable legal company identity, optional address/phone, order details, itemised products/options, units, unit price, total, payment/delivery details, receipt footer, and a strong mobile/print layout. Never include copied company details by default.
- Inventory products, stock movements, stock alerts, warehouse locations, warehouse requests, approvals, issuance, return custody, return acceptance, quarantine, stock transactions, audit events, and manager notices.
- Commercial records, stock accounts, balances, stock events, campaigns, campaign deliveries, customer portal accounts, and idempotent commercial operations.
- Delivery proof, order fulfilment, payments and collections.
- If multi-row cloud writes cannot be performed transactionally with the chosen data layer, do not falsely report success. Use a database RPC/transaction adapter or clearly block that operation with a recoverable, visible error until it is implemented. Do not leave dead UI buttons.

### 10. Maps and Leaflet/OpenStreetMap

- Use Leaflet with OpenStreetMap tiles; do not depend on a paid Google Maps API key.
- Include graceful tile/network failure UI: a clear status message, retry, list/table fallback, and no blank map area.
- Show work locations, 300m market rings, customer pins, route points, active field telemetry where permitted, and a non-map fallback.
- Lazy-load map components and keep map assets out of critical login rendering.
- Validate and sanitize all coordinate inputs. Do not use map position as employment decision evidence without an authorised review path.

### 11. Reports, exports, daily email, and intelligence

Build a reporting centre for HR/admin/superadmin:

- Excel `.xlsx` exports for staff, attendance by name/location, sales, tasks, leave, field visits, warehouse, delivery, and daily operational summaries.
- Daily report system configurable by admins: multiple recipient email addresses, enable/disable schedule, delivery history, error states, report date, and test send. Default recipient may be `hr@experiential-edge.com` only if it is entered in configuration, never hard-code it as an irreversible destination.
- Daily report should include sales, attendance by name and location, late/missed clock-ins, SOS/movement/activity flags, incomplete tasks by person and project, leave items, field visits, and delivery/warehouse exceptions as available.
- Use Gmail SMTP or compatible SMTP only from server environment variables: `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS`, `EMAIL_FROM`. Do not commit SMTP credentials. Use an app password, not a personal Gmail password.
- Vercel scheduled route is protected by `CRON_SECRET`. It must reject unauthenticated requests.
- Include a NEXUS Intelligence Centre: executive overview, factual KPI cards, operational trends, exceptions, evidence links, source calculations, root-cause hypotheses clearly labelled as hypotheses, uncertainty/coverage markers, and recommendations.
- AI is optional. All dashboards must still work without an external AI provider. For AI explanations use a pluggable private model gateway configured by `NEXUS_MODEL_PROVIDER`, `NEXUS_MODEL_URL`, `NEXUS_MODEL_API_KEY`, and `NEXUS_MODEL`; do not require OpenAI. Ground any AI response in verified application facts and never invent metrics.

### 12. Data model and migration contract

Create one clean-install Supabase SQL file plus ordered idempotent migrations. The clean installer must create the complete schema without importing any operational data. It must run in a transaction where practical and finish with a PostgREST schema reload.

At minimum the schema must cover these groups:

- Tenant/company, company settings, departments, ranks, users, employees, employee number issuance/corrections/archive history.
- Work locations, employee location assignments/history, attendance, attendance exceptions, workplace sessions, movement events/notices.
- Leave types, leave balances, leave requests/approvals, recruitment, onboarding, announcements, notifications, audit logs, documents, payroll/payslips.
- SOS and SOS events with `accuracy`, activity/presence/idle events/notices, schedules.
- Customers, products, stores, orders, order items, payments, commissions, visits, field audits, deliveries, inventory, inventory movements/transactions/alerts.
- Collaboration projects/members/channels/messages/tasks/events/notices.
- Warehouse managers/requests/request lines/returns/events/notices/operations/stock locations.
- Commercial records/operations/balances/stock events/portal accounts/campaign deliveries.
- NEXUS report data/settings and HR report delivery history.

Before declaring complete, automatically compare literal server table references to tables in the clean installer. The check must produce zero missing production table references. Also verify fields that have previously caused schema-cache failures, including `leave_balances.annual`, `sos.accuracy`, work location geofence fields, collaboration task fields, and all SOS event fields. Never use `bigint` or `bigserial`.

### 13. API and UI workspaces

Provide cohesive role-based dashboards, not an unrelated collection of pages:

- Employee: today, assigned workstation, attendance, leave, tasks, notices, profile, payslips.
- HR: people directory, import, archive/restore, numbers, leave, recruitment, attendance, schedules, locations/assignments, compliance, reports.
- Supervisor: team tasks/schedules, team attendance, field visibility, exceptions.
- Sales/field: customer routes, visits/audits, orders, collections, stock, map, task centre.
- Inventory/warehouse: products, stock levels, requests, approvals, issue/return flows, alerts.
- Finance/accounting: settlements, compensation/payslips, accounting reports.
- Executive/super admin: command centre, organisation/roles, company/receipt settings, intelligence, security/audit, report recipients, integrations.

### 15. Mandatory verification before handoff

Do not claim completion until all of these pass:

1. Frontend production build passes.
2. Backend test suite passes, including registration, staff number generation, correction, archive/restore, role restrictions, attendance location validation, workplace session revoke, inactivity threshold, SOS flow, collaboration peer task assignment, report exports, and schema contracts.
3. Database clean installer runs in a fresh Supabase project with no operational records inserted.
4. Schema audit shows zero missing literal production table references.
5. Verify Supabase tables can select expected columns: `leave_balances.annual`, `sos.accuracy`, `sos_events.accuracy`, `work_locations.geofence_radius_meters`, and collaboration task fields.
6. Create two storage buckets, one public media and one private document bucket. Test public upload/read/cleanup and private upload/signed-read/cleanup.
7. Deploy to Vercel. Confirm `/`, `/api/health`, `/api/health/ready`, unauthenticated `/api/auth/me` (401), super-admin login, authenticated `/api/auth/me`, HR dashboard, locations, collaboration overview, reports settings, and SOS list.
8. Manually inspect the responsive sign-in page and at least one role dashboard on desktop and mobile widths. Confirm no old product/company name, old cache key, copied company address, or copied company phone appears in public-facing text.
9. Commit only code, migrations, documentation, and safe static assets. Confirm no `.env`, credentials, exports, uploads, customer data, staff data, or database dumps are tracked.

### 16. Delivery format

At the end provide:

- A short release summary.
- Links/paths to the clean installer, migrations, environment template, deployment instructions, API documentation, database documentation, and test commands.
- The live URL and repository URL if deployed.
- A concise table listing the verified modules and the checks used.
- Any truly unresolved third-party setup requirement (for example, Gmail app password or GitHub re-authentication), with the exact user action required. Do not call the system “fully live” if that prerequisite prevents a declared feature from functioning.

## Reuse notes

For a new brand, replace `[BRAND_NAME]`, `[PRIMARY_COLOR]`, `[ACCENT_COLOR]`, and `[NEUTRAL_PALETTE]`. Keep the role, database, test, and security requirements unchanged. This prompt describes the product contract; it deliberately excludes credentials and operational records.
